# Complete Cargo Anvil adoption

## Goal

Make Cargo Anvil the only implementation of Rust validation, remove obsolete
legacy infrastructure, and preserve only documented repository-specific
contracts outside Anvil's scope.

## Deferred follow-up work

This cleanup does not block on closing behavioral differences between legacy
checks and Anvil. Track and address these independently:

- `cargo-coverage-gate` rounding at a 100% threshold;
- mutation test-package groups formerly implemented by `scripts/mutants.rs`;
- the cargo-machete backstop not supplied by `anvil-udeps`; and
- the exact `internity` `no_std + serde` compile-fail configuration.

The cleanup intentionally adopts current Anvil behavior and removes the legacy
implementations. The follow-up work must change Anvil-supported configuration
or the Anvil catalog rather than restoring parallel repository checks.

## Capability migration

| Legacy capability | Anvil replacement | Migration |
| --- | --- | --- |
| Delta calculation in `main.yml` | `anvil-impact` and generated impact actions | Delete the legacy job and use Anvil impact artifacts. |
| Build and feature validation | `anvil-build`, `anvil-clippy`, `anvil-cargo-hack`, `anvil-msrv-test` | Adopt Anvil arguments and scheduling; do not preserve the legacy command lines. |
| Unit, integration, and doc tests | `anvil-llvm-cov` and `anvil-doc-test` | Delete duplicate test recipes and workflow steps. |
| Example build and execution | `anvil-examples` | Migrate examples from `IS_TESTING` to `ANVIL_EXAMPLE`, add `employees` to package `no-run` metadata, then delete `scripts/run-examples.rs`. |
| Formatting and manifest sorting | `anvil-fmt` and `anvil-cargo-sort` | Delete legacy format recipes. |
| README generation/checking | `anvil-readme --fix` and `anvil-readme-check` | Delete cargo-workspaces wrappers and its tool pin. |
| Clippy, licenses, spelling, deny, audit, dependency shape | `anvil-pr-fast` checks | Delete duplicate recipes and jobs. Preserve policy in Rust, Clippy, spelling, and deny configuration. |
| External-type exposure | `anvil-external-types` | Delete `scripts/check-external-types.rs`; keep per-package allowed-type metadata. |
| SemVer PR advisory | `anvil-semver-check` | Delete `scripts/ci/semver-report.ps1` and only the Pester tests specific to that CI report. Keep release planner SemVer logic and tests. |
| Careful and standard Miri | `anvil-careful` and `anvil-miri` | Delete legacy jobs and recipes. |
| Tree-borrows, strict-provenance, and race-coverage Miri | generated scheduled runtime-analysis group | Move `.miri-tree-borrows-skip` entries to narrowly scoped `cfg_attr(miri_tree_borrows, ignore = "...")` attributes, then delete the suppression file. |
| Loom and Bolero | `anvil-loom` and `anvil-bolero` | Update design/docs references and delete legacy implementations. |
| Diff and full mutation testing | `anvil-mutants-diff` and `anvil-mutants-full` | Delete `scripts/mutants.rs`; keep the common cargo-mutants policy and use complete host-specific configurations for its former target exclusions. Test-package grouping remains deferred. |
| Coverage generation and enforcement | `anvil-llvm-cov` plus `cargo-coverage-gate` | Delete legacy coverage recipes/job. Keep Codecov upload display-only. |
| Nightly gatekeeper and failure issue | generated scheduled workflow | Adopt Anvil's schedule and failure publisher; delete `nightly.yml`. |
| Repeated metabench subprocess stress job | No direct replacement | Remove it. It is historical CI customization rather than a separately documented product contract. |
| Release PowerShell tests | No Anvil replacement | Retain as a focused repository-specific recipe and workflow. |

## Repository cleanup

1. Resolve the current `cargo anvil --dry-run` plan before other edits:
   - accept the five proposed crate lint regions;
   - investigate the three lint regions whose ownership would transfer; and
   - reconcile the seven customized managed regions, including the coverage
     recipe, without forcing generated content.
2. Delete `.github/workflows/main.yml` and
   `.github/workflows/nightly.yml`.
3. Delete `.github/actions/setup/action.yml` after all retained workflows use
   Anvil setup or a narrower repository-owned setup.
4. Migrate `publish-gh-release.yml` away from `constants.env` and the legacy
   setup action while retaining the release workflow itself.
5. Remove duplicate imports and recipes from the root Justfile:
   `basic.just`, `coverage.just`, `extended.just`, `format.just`,
   `setup.just`, and `spelling.just`.
6. Retain only focused repository utilities that Anvil does not provide, such
   as Pester execution, trybuild iteration, and license-header repair, in a
   short repository-specific section of the root Justfile. Do not retain
   aliases for Anvil checks.
7. Delete obsolete helper scripts:
   - `scripts/check-external-types.rs`;
   - `scripts/run-examples.rs`;
   - `scripts/ci/semver-report.ps1`;
   - `scripts/mutants.rs`;
   - `scripts/update_tool_versions.ps1`;
   - `scripts/update_rust_toolchain.ps1`; and
   - `scripts/update_action_versions.ps1`, because Dependabot owns
     repository-owned Actions updates and `cargo anvil` owns generated files.
8. Delete `constants.env`. Migrate every remaining consumer in the same change:
   generated Anvil recipes use `justfiles/anvil/versions.just`; release
   publishing installs only the toolchain it needs; VS Code uses the Anvil
   nightly pin; release-script guidance names the Anvil setup command; and
   retained non-Anvil tools derive their version from their actual manifest
   dependency rather than another constants file. Remove duplicate per-crate
   correctness scripts where they merely reproduce the Anvil suites.
9. Keep Codecov project and patch statuses for detailed coverage visibility,
   but remove comments and notification settings tied specifically to the
   deleted legacy coverage matrix. Codecov remains a reporting surface; the
   Anvil coverage gate is authoritative. The statuses stop blocking merges
   only when the maintainer removes them from the repository ruleset.
10. Update source and documentation references:
    - change example automation checks from `IS_TESTING` to `ANVIL_EXAMPLE`;
    - replace legacy Just commands in `README.md`, `DEVELOPMENT.md`, crate
      design docs, and agent instructions;
    - point CI badges in `README.md` and `crates/README.j2` to
      `anvil-pr.yml`;
    - regenerate crate READMEs with `just anvil-readme --fix`; and
    - remove stale comments naming deleted scripts, workflows, constants, and
      recipes.

## Retained infrastructure

Keep these because Anvil does not own their capability:

- `.github/workflows/codeql.yml`, required by the repository code-scanning
  rule;
- `.github/workflows/publish-gh-release.yml` and release scripts;
- `.github/dependabot.yml`;
- the CLA integration and organization/repository review rules;
- release-planner Pester tests and a focused workflow that runs them; and
- repository policy files consumed by Anvil, including `.delta.toml`,
  `deny.toml`, `.spelling`, `clippy.toml`, Rust lint tables, coverage metadata,
  external-type metadata, and `.cargo/mutants*.toml`.

## Ruleset transition

The active `main` ruleset currently requires:

- `license/cla`;
- `required-checks`;
- `codecov/patch`; and
- `codecov/project`.

The repository cleanup PR cannot perform this privileged update. The maintainer
must coordinate the merge with an atomic ruleset update:

1. add `Required Anvil checks`;
2. add any intentionally retained repository-specific fan-in;
3. remove `required-checks`, `codecov/patch`, and `codecov/project` from the
   required-context list while allowing Codecov to continue posting its
   informational statuses; and
4. leave `license/cla` and the CodeQL code-scanning rule intact.

Do not merge the workflow deletions before this ruleset update is ready, or the
deleted contexts will remain permanently expected.

## Verification

1. Run each Anvil replacement corresponding to a removed legacy capability,
   using `ANVIL_IMPACT=off` when a full-workspace comparison is required.
2. Run the retained repository-specific suite on Linux and Windows.
3. Run `cargo anvil`, then require a clean `cargo anvil --dry-run`.
4. Run `just anvil-pr-fast`, followed by the complete `just anvil-pr` tier.
5. Search for deleted workflow names, old recipe names, `constants.env`,
   `IS_TESTING`, deleted helper scripts, and stale CI badge targets.
6. Confirm the PR reports `Required Anvil checks`, the retained
   repository-specific status if any, and informational Codecov results without
   required Codecov statuses.
