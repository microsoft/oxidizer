# AI Agents Guidelines for `routerama`

Code in the `routerama`, `routerama_build`, and `routerama_macros` crates should follow the
[Microsoft Rust Guidelines](https://microsoft.github.io/rust-guidelines/agents/all.txt), with the
crate-local conventions below taking precedence where they differ.

## Documentation

### One worked example per module, not per item

[C-EXAMPLE](https://rust-lang.github.io/api-guidelines/documentation.html#c-example) asks for a
worked example on every public item. These crates deliberately follow a **per-module** rule
instead: each module and each primary type carries at least one worked example showing idiomatic
use, and the supporting items in that module rely on it rather than repeating it.

The reason is that most public items here are not independently invocable. Handler dispatch,
extraction, and response composition are generated by `#[router]` and `#[resolver]`, so the
majority of the public surface is either a type appearing in a generated signature or a helper
called only from generated code. A per-item example would have to restate the surrounding
`#[router]` impl to compile, which produces near-identical examples that obscure the one example
that actually teaches the module.

When adding public API:

- If it introduces a new module or a new primary type, add a worked example.
- If it extends an existing module, do not add an example unless the item is used in a way the
  module's existing example does not already demonstrate.
- Prefer improving the module's example over adding a second one.

Examples must still compile: they are doctests, and doctests that reference feature-gated items
must compile both with and without the feature. See
[`docs/feature-gated-doctests.md`](../../docs/feature-gated-doctests.md) for the hidden-`#[cfg]`
shim pattern.

### Summary sentences

The first sentence of every doc comment must fit on one line and stay within about 15 words, per
[M-FIRST-DOC-SENTENCE](https://microsoft.github.io/rust-guidelines/guidelines/docs/#M-FIRST-DOC-SENTENCE).
Detail, caveats, and rationale belong in the body after a blank `///` line. Nothing enforces this
mechanically — `clippy::too_long_first_doc_paragraph` is not in the workspace lint table — so it is
a review responsibility.

## Performance

Design decisions in these crates are weighed against generated-code quality first. Prefer moving
work into `routerama_build` codegen over doing it at request time, and prefer a larger generated
match over a runtime lookup. See [`docs/PERF.md`](docs/PERF.md) for measured results and
[`benches/README.md`](benches/README.md) for the three benchmark families and which audience each
serves.
